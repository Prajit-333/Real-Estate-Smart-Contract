Important note about the refund function
The contract contains:


However, a normal purchase usually transfers the money directly to the seller and changes the property to Transferred. The refund path is intended for a special case where the seller cannot receive ETH and the automatic payout fails.

Therefore, it may not be possible to demonstrate refundBuyer() using only normal externally owned Hardhat accounts. You can explain it during the presentation as an emergency recovery path:

If payment reaches the vault but seller payout fails, the property remains in the Paid state and the verifier can refund the buyer.

The related implementation is in RealEstateVault.sol.

What to show in the Activity tab
At the end, open Activity and explain that every important operation creates an on-chain event:

Event	Meaning
PropertyRegistered	Owner registered a new property
PropertyRejected	Verifier rejected the documents
PropertyReRegistered	Owner submitted a corrected document hash
PropertyVerified	Verifier approved the property
PaymentDeposited	Buyer sent the exact purchase amount
OwnershipTransferred	Ownership changed and seller was paid
VerifierChanged	Admin changed the verifier
The event display is implemented in App.jsx.

Short explanation for the payment issue
You can state:

Registration does not transfer the sale price. It only stores the document hash and price on-chain. MetaMask still charges gas because registering is a blockchain transaction. The actual property amount is transferred only during the purchase step after verifier approval.
